# RoundedDie Hold-v1 实现说明

本实验是 RoundedDie Smooth-v1 的独立源码副本，分支 `codex/rounded-die-hold`。
任务 ID 为 `Isaac-ViserDex-Repose-Revo3-SuperMimic-RoundedDie-Hold-v1`。
原骰子、球体、原始 SuperMimic 和 student PPO 目录均不参与本次修改。

## 成功与切换规则

每个物理控制步结束后，用真实物体姿态、当前目标姿态和物体角速度计算：

| 条件 | 设置 |
|---|---|
| SO(3) 姿态误差 | 严格小于 0.1 rad，约 5.73° |
| 物体角速度向量模长 | 严格小于 0.5 rad/s，约 28.65°/s |
| 连续保持 | 10 个合格控制样本，20 Hz 下计为 0.5 s |
| 中途姿态/角速度超标，或出现非有限数 | 保持计数清零，重新连续累计 |
| 掉落、超时或其他终止 | 清除该环境计数，不在结束的这一步奖励成功 |
| 达到第 10 个合格样本 | 一次成功奖励、一次成功计数、一次新目标采样，保持计数清零 |

判断发生在控制采样时刻，没有检查 120 Hz 子步之间的持续合格情况。
保持期间继续每步输出控制动作，目标保持原值；不会暂停物理仿真。
目标依旧从原来的 q_x(alpha) * q_y(beta) 分布采样。
到位但角速度过大、快速掠过目标、仅保持 9 步均不能获得成功奖励。
新目标可以继续运动，下一次成功仍需重新满足完整保持条件。

这项修改抑制“刚碰到目标就马上追下一目标”的任务激励；它不是关节速度硬限幅，
也不保证尚未训练的策略已经平稳。手指是否更慢、保持是否稳定，仍需要生产训练和视频评估。

## 真实环境、想象训练与统计

`goal_hold.py` 是共享的纯 Torch 判定函数。`hold_command.py` 在官方 manager 生命周期中
于奖励计算阶段更新一次计数。计数更新按 `common_step_counter` 去重；官方复位完成后，
command 更新阶段只对未复位的成功环境重采目标。没有修改 Newton、MuJoCo Warp 或 Isaac Lab 源码。

Recorder 在自动复位和目标切换之前捕获物体状态、角度、角速度、计数和成功事件。
Adapter 从前一步状态独立重算事件，逐步核对奖励、计数、目标未切换条件和成功总数。
复位仅清理相应环境，防止跨回合继承保持进度。

世界模型仍只预测 55 维物理状态；保持计数由任务代数确定性推进。
`Trainer.imagine()` 的成功奖励和目标切换使用同一判定，并将进度传给下一想象步。
特权状态末尾新增索引 172，完整状态 172→173 维；四元数特征化后的任务特征 176→177 维。
Critic 增加此输入，Actor 观测仍为 **10×124**，不额外读取真实角速度或保持计数。
Replay 保存新计数；检查点升级为 **v15**，训练、播放和导出拒绝旧 v14 检查点。

训练日志中的 successes、goals_per_completed_episode 和视频 Goals 均统计完整保持成功，
不再统计瞬时角度达标。视频仍显示目标姿态，并增加角速度及 0.5 s 保持进度。

物理世界模型的留出评估仍是给定真实动作的开环物理预测；其 reward_mae 使用真实记录中的
目标和保持上下文评估当前物理预测误差，不代表整段自主目标切换预测误差。

## 保留设置

| 项目 | 设置 |
|---|---|
| 物体 | rounded_die，70 mm，60 g，原凸碰撞网格；非 Gaussian 渲染训练 |
| 初始位置 | (0.02, -0.01, 0.565) m，沿用用户确认的掌内位置 |
| 物理/控制 | Newton MuJoCo Warp；120 Hz / 20 Hz |
| EMA 新目标系数 | 0.5 |
| 控制器 | 原 PD/隐式执行器配置，kp=7，kd=0.22，力矩上限 0.6 Nm |
| 姿态稠密奖励 | 1 / (angle_error + 0.1) |
| 成功奖励系数 | 166.6666667，保持完成才发放；乘控制 dt 后约 8.3333 |
| 关节速度平方惩罚 | -0.00003125 |
| 动作幅度平方惩罚 | -0.000125 |
| 动作一阶差分平方惩罚 | -0.005555555556 |
| 动作二阶差分平方惩罚 | -0.005555555556 |
| 观测噪声、延迟、异常值和域随机化 | 继承当前骰子配置，不增加外力扰动 |
| 回合长度 | 20 s；原距离掉落规则和 50 次成功上限保留 |
| 世界模型监督 / 策略想象 | 8 步 / 8 步 |
| 生产规模 | 两卡同步，2048 环境/卡，总 4096 |
| 初始化 | 从头训练，500 轮 WM 预热和原策略学习率爬升 |

惩罚表中的权重均为 RewardManager 乘 0.05 s 前的系数。保持时不增加额外位置奖励。
本次保留 8 步想象长度，小于完整保持所需的 10 步；从已有部分保持进度的 Replay 状态
可以在 rollout 内完成，较远回报通过包含进度的 Critic bootstrap 估计。没有宣称这能保证收敛。

## 入口与隔离

服务器源码：`/home/zhangke/viserDex_supermimic_rounded_die_hold_20261031/repository`。
配置：`configs/rounded_die_hold/env.yaml`。现有配置已生成；`prepare_hold.py` 拒绝覆盖。

进程状态：`outputs/active_rounded_die_hold.json`。

在服务器此独立源码目录、配置好原官方运行时后：

```bash
python scripts/supermimic/start_hold.py --start-training --gpu GPU_UUID_A --gpu GPU_UUID_B
```

需要两张明确选择的空闲 GPU。启动器拒绝已有输出路径或被占用的卡；不会停止原训练。
这条生产命令与用于验证的 `--smoke` 命令分开。小规模测试权重不能当成正式训练结果，
播放脚本会拒绝 smoke 检查点。

检查点仍包含世界模型、Actor、Critic、优化器、配置和元数据。只在新任务内恢复 v15；
恢复语义沿用权重/优化器恢复并重新初始化仿真和 Replay，不是位级连续复现。
